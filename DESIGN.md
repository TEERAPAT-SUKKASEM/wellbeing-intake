# Visual direction: approachable campus support

The user requested a completely new redesign using ui-ux-pro-max. This replaces the previous dark photographic glass interface with a bright, approachable student portal across all screens. Product behavior, roles, privacy boundaries, emergency contacts, API contracts, and existing demo data remain intact.

## Foundations

Next.js 16, Tailwind 4, and daisyUI 5. Geist provides body and control text. Manrope provides functional headings at 550–600 weight. DM Serif Display supplies editorial welcome headings with restrained italic emphasis. All fonts are bundled locally in src/app/fonts and served through next/font/local, with their OFL notices included; builds and page rendering do not fetch font files from external servers. Standard body text is 16px, with 13–14px supporting text on compact surfaces. Balanced headings, consistent measures, and restrained negative tracking keep the reading hierarchy clear.

Semantic daisyUI tokens: base-100 #ffffff, base-200 #f7f8f6, base-300 #dfe5e6, base-content #253542, primary #315b91 with white content, secondary #dfecf7 with #254b80 content, accent #f8dac6 with #713e20 content, neutral #243244 with white content, success #23705a, warning #86570b, error #922439. Supporting surfaces are blue #eef3f8, mint #edf5ef, and apricot #fdf0e6. Secondary copy uses #3f505d. Pastels provide orientation; text and controls use darker colors with sufficient contrast.

The application uses a 232px fixed desktop sidebar at widths of 1024px and above, a 76px sticky context header, and a content workspace with 32px gutters and a 1440px maximum width. Phones use 20px gutters. Cards use 16px radii and a single subtle border; control radii are 10px, with at least 44px touch targets. The user requested premium glassmorphism. A clearly visible, full-opacity campus photograph fills the fixed page background. The picture itself is not blurred; translucent content panels apply the frost over it. Glass uses 76% white fill, a 92% white edge, 18px backdrop blur, and a soft 0 12px 32px shadow at 7% opacity. Navigation uses 24px blur. Inputs and emergency content use steadier surfaces. The photograph and blur remain static; unsupported backdrop filters use near-opaque surfaces, and reduced-transparency preferences remove the effects.

Calls to action name the next action: Find my support, service-specific request labels, Send private request, and booking confirmation with the selected time. Primary actions use filled blue controls at least 52px tall, with full-width placement on small screens. Service requests use pale-blue outlined controls; navigation and destructive alternatives remain secondary. Pending actions retain blue styling with a spinner, explicit progress text, aria-busy, and disabled duplicate submission. Hover adds restrained depth to primary controls and a short arrow movement to service links; reduced motion disables transitions. Request submission explains practitioner review before booking, with urgent guidance kept separate.

## Composition

The homepage starts with an editorial frosted welcome panel, leaving part of the full-page campus photograph visible beside it. The separate hero photograph is removed. Photography is illustrative, with that disclosure in the footer. Section headings and route introductions also sit on glass reading surfaces so no essential text sits directly over the photograph. A single-column service catalogue uses horizontal rows on desktop, with service identity, description, expandable first-visit/privacy details, and a service-specific request action. At 1280px and above, the optional matching helper sits in a sticky 280px right column. At smaller widths the helper follows the catalogue in both DOM and visual order. Emergency contacts remain above the catalogue and accessible from every route's navigation. Counselling uses blue, clinic apricot, physiotherapy mint, and advising muted violet for consistent icon accents.

Sign-in uses an apricot introduction beside a white form, with equal panel heights on desktop, password reveal, and required-field feedback. Service cards keep the description and request action visible; native disclosures hold first-visit and privacy details. The request form places privacy information beside the fields on desktop and before them on mobile. Request and booking controls use white surfaces with visible borders, inline labels, focus states, and error feedback. Student request cards lead with service and status, followed by compact progress for active requests; handled requests without appointments do not show an unfinished booking sequence. Student and staff summaries derive their counts from loaded data. Staff tables remain horizontally scrollable within their containers on narrow screens, with section headings outside the table surface. Emergency contacts have explicit call actions.

Desktop and mobile navigation show the role-specific workspace link when signed in, followed by the four campus services and then Emergency contacts immediately after Wellbeing advising. The redundant Explore services navigation entry is omitted; the logo still links home. The desktop sidebar also contains account actions. A keyboard-accessible, background-free double-arrow toggle at the top-right of the sidebar, above the logo, shrinks it to a 76px icon rail and expands the workspace. Icon links retain accessible text names and native hover labels. The choice stays in memory across client navigation, without browser storage, and does not alter the mobile dialog. Service deep links scroll after asynchronous catalogue loading. The context header shows the current screen and signed-in display name. Below 1024px, a sticky mobile header opens native dialog navigation with Escape, focus containment, and focus restoration. The product name remains Campus Health & Wellbeing; the compact brand mark uses the existing SVG wellbeing icon.

Student requests use a main task column and a 280px summary/privacy column at 1280px and above; the context follows the requests on smaller screens. The practitioner workspace places the request queue and audited request details beside a 300px availability column on wide screens, stacking them at smaller widths. Coordinator tables occupy the full workspace width. Forms retain the dedicated privacy sidebar on desktop, while the sign-in screen keeps its paired introduction and form inside the shared application shell.

## Motion and accessibility

One short opening entrance, 160ms navigation and control feedback, smooth anchor scrolling, a brief details reveal, and a short booking-confirmation reveal, all disabled for reduced motion. The catalogue offers an in-place retry after loading failure and returns keyboard focus to its heading after recovery. Next.js receives the smooth-scroll attribute so route scroll restoration remains predictable. Urgent follow-up requests appear first, then ready-to-book requests, confirmed appointments, requests awaiting review, and handled requests; source order is preserved within each group. Ready-to-book cards state that action explicitly. Visible blue keyboard focus indicators, themed selection and caret colors, stable button dimensions, consistent SVG strokes, and explicit loading/error/empty states. Emergency pages have no backend dependency. The helper's privacy and urgency limitations remain visible. Existing authenticated and preview flows share the same request components.

Direction was reviewed directly against its local Healthcare App and Mental Health App product rows (calm colors, accessibility, privacy, crisis resources), Flat Design and Soft UI Evolution style rows (clear hierarchy, visible focus, 150–300ms transitions), and the quick-reference accessibility, form, navigation, and responsive guidance. The palette and composition above are authored project decisions, not generated search output.
